# Спек бэкенда: репозиторий работ факультета

Oct 12, 2026 · @Daniil

Бэкенд — пять сервисов на Python 3.15, FastAPI, pydantic и SQLAlchemy поверх одной PostgreSQL. События идут через RabbitMQ, файлы лежат в MinIO, карточки ВКР заполняет локальная LLM. За основу взят Doc: слои, Unit of Work, DI, `shared`, шина и CI берутся оттуда без изменений, здесь — только то, что добавляет или меняет наш проект. Контракт с фронтом — раздел 7 и дополнения в README фронтенда.

## Архитектура

&#91;embedded content: архитектура · 4 HTTP-сервиса, воркер, PostgreSQL, MinIO, RabbitMQ, LLM\]

nginx отдаёт фронт и разводит `/api` по четырём HTTP-сервисам по префиксу пути. Долгий разбор архивов уходит через RabbitMQ в extraction\_worker, а файлы браузер берёт из MinIO напрямую по presigned-ссылке. Логи и метрики всех контейнеров собирают Alloy, Loki и Prometheus, смотрим их в Grafana; на схеме они не показаны.

## Сервисы и маршрутизация

Четыре HTTP-сервиса делят REST по префиксу пути, а nginx маршрутизирует по этим префиксам. Фронт продолжает ходить на `/api/...`, как сейчас. Сервисы не вызывают друг друга по HTTP: общие данные читают из одной базы через `shared/repository`, а долгую работу передают через шину.

| Сервис | Пути | Что делает |
| --- | --- | --- |
| `auth_service` | `/api/auth/*` | Пользователи, хэш пароля, JWT в куку, `/auth/me`. Единственный сервис, который знает пароли |
| `catalog_service` | `/api/works*`, `/api/people*`, `/api/departments`, `/api/stats`, `/api/upload-limits`, `/api/client-errors` | Публичный каталог: поиск, фасеты, `view`, ГОСТ, ссылки на файлы. Только чтение (`uow_ro_factory`), поэтому можно запускать несколько реплик |
| `admin_service` | `/api/admin/works*`, `/api/admin/people*`, `/api/admin/summary`, `/api/admin/events`, `/api/admin/exports/*`, `/api/my/*` | Редактор, проверки `errors` / `issues` / `actions`, публикация, bulk, очередь проверки, DOI через Crossref, слияние людей, выгрузки, кабинет автора: свои работы и материалы |
| `import_service` | `/api/admin/imports*`, `/api/admin/templates*` | Загрузка, preview таблиц, синхронный разбор таблиц, приём архивов, черновики из результатов воркера |
| `extraction_worker` | без HTTP, только шина и `/healthcheck` | PDF → текст → регулярки и LLM → поля с confidence |

Имена: сервисы с HTTP API — `*_service`, воркеры без API — `*_worker` с именем по назначению. Таблицы и архивы остаются в одном сервисе: оба идут в `POST /admin/imports`, а nginx маршрутизирует по пути, не по полю формы. WebSocket и `connection_service` из каркаса не нужны: прогресс импорта фронт опрашивает раз в 3 секунды.

К модулям `shared` из каркаса добавляется:

| Модуль | Что даёт | Кто пользуется |
| --- | --- | --- |
| `auth.py` | Выпуск JWT (только auth) и проверка подписи Ed25519, зависимости `current_user`, `require_moderator`, `require_author` | auth, admin, import |
| `names.py` | Нормализация ФИО, сопоставление авторов по `aliases` | admin, import |
| `storage.py` | MinIO: `put`, `get`, `presign` | catalog, admin, import, extraction\_worker |
| `config.py` | Добавляются `S3Config`, `LLMConfig`, лимиты загрузки | все |

Остальное живёт в своём сервисе. `view` и ГОСТ — в catalog, проверки черновиков и шаблон новой работы — в admin, поиск дублей и колонки таблиц — в import. Эталон поведения — моки фронта в `src/mocks`, а `logic.test.ts` переносится в pytest. Вычисляемое не храним: `stats` импорта, `counts`, `byYear`, `view`, `errors`, `issues`, `actions` собираются при чтении.

Роутеры всех сервисов — с `prefix="/api"`. nginx префикс не срезает (`proxy_pass` без слэша) и выбирает самый длинный подходящий `location`:

```nginx
# frontend/nginx.conf.template
limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;
limit_req_zone $binary_remote_addr zone=client_errors:10m rate=30r/m;

server_tokens off;
client_max_body_size 1m;   # больше — только на путях загрузки ниже
ssl_certificate     /etc/nginx/certs/fullchain.pem;
ssl_certificate_key /etc/nginx/certs/privkey.pem;
# если перед nginx стоит прокси вуза: set_real_ip_from <его адрес>; real_ip_header X-Forwarded-For;

server {
    listen 80 default_server;
    return 301 https://$host$request_uri;
}

# сайт: фронт и API на одном origin
server {
    listen 443 ssl;
    server_name ${SITE_DOMAIN};
    gzip on;
    gzip_types application/json text/css application/javascript;

    # заголовки — только на уровне server: location со своими заголовками эти не унаследует
    proxy_set_header Host $host;
    proxy_set_header X-Request-ID $request_id;
    proxy_set_header X-Forwarded-For $remote_addr;
    add_header X-Request-ID $request_id always;
    add_header Strict-Transport-Security "max-age=31536000" always;
    add_header X-Content-Type-Options nosniff always;
    add_header Referrer-Policy same-origin always;
    add_header Content-Security-Policy "default-src 'self'; img-src 'self' data: https://files.${SITE_DOMAIN}; frame-src https://files.${SITE_DOMAIN}; style-src 'self' 'unsafe-inline'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'" always;

    location = /api/auth/login     { limit_req zone=login burst=5 nodelay; proxy_pass http://auth_service:8000; }
    location /api/auth/            { proxy_pass http://auth_service:8000; }

    # загрузки: лимиты = maxBytes из /api/upload-limits; аноним получает 401 до приёма тела
    location /api/admin/imports                  { auth_request /_auth; client_max_body_size 500m; proxy_request_buffering off; proxy_pass http://import_service:8000; }
    location ~ ^/api/admin/works/[^/]+/file$     { auth_request /_auth; client_max_body_size 100m; proxy_request_buffering off; proxy_pass http://admin_service:8000; }
    location ~ ^/api/my/works/[^/]+/materials$   { auth_request /_auth; client_max_body_size 50m; proxy_request_buffering off; proxy_pass http://admin_service:8000; }
    # свой proxy_set_header: заголовки server сюда не наследуются, для /auth/me они не нужны
    location = /_auth { internal; proxy_pass http://auth_service:8000/api/auth/me; proxy_pass_request_body off; proxy_set_header Content-Length ""; }

    location /api/admin/templates  { proxy_pass http://import_service:8000; }
    location /api/admin/exports/   { proxy_buffering off; proxy_pass http://admin_service:8000; }
    location /api/admin/           { proxy_pass http://admin_service:8000; }
    location /api/my/              { proxy_pass http://admin_service:8000; }
    location = /api/client-errors  { limit_req zone=client_errors burst=20; client_max_body_size 16k; proxy_pass http://catalog_service:8000; }
    location /api/                 { proxy_pass http://catalog_service:8000; }
    location ~ \.map$              { return 404; }   # sourcemap — для разбора стеков, не для всех
    location /                     { root /usr/share/nginx/html; try_files $uri /index.html; }
}

# файлы: presigned-ссылки и фото; путь не переписываем, иначе подпись SigV4 не сойдётся
server {
    listen 443 ssl;
    server_name files.${SITE_DOMAIN};
    add_header Strict-Transport-Security "max-age=31536000" always;
    add_header X-Content-Type-Options nosniff always;
    location /minio/ { return 404; }   # health, метрики и admin API MinIO
    location / {
        limit_except GET HEAD { deny all; }   # снаружи MinIO только читается
        proxy_set_header Host $host;
        proxy_pass http://minio:9000;
    }
}

# статистика: Grafana только из сети вуза
server {
    listen 443 ssl;
    server_name stats.${SITE_DOMAIN};
    allow ${STATS_ALLOW};
    deny all;
    location / { proxy_set_header Host $host; proxy_pass http://grafana:3000; }
}
```

Конфиг — шаблон: официальный образ nginx при старте подставляет `${SITE_DOMAIN}` и `${STATS_ALLOW}` из окружения и не трогает переменные nginx вроде `$host`. Regex-location (загрузки, `.map`) выигрывают у префиксных, кроме `=`.

Тело больше 1 МБ принимают только три пути загрузки. На них `auth_request` спрашивает `/api/auth/me` до приёма тела: аноним сразу получает 401, а не после того, как nginx запишет 500 МБ во временный файл. `proxy_request_buffering off` отдаёт тело сервису потоком.

CSP: inline-скриптов в сборке нет; `style-src 'unsafe-inline'` нужен атрибутам `style` (Recharts); картинки и iframe с PDF — только с `files.<домен>`. `frame-ancestors 'none'` не даёт встроить сайт в iframe: с соседнего поддомена Lax-кука в iframe ушла бы, и кликджекинг прошёл бы мимо Origin-check.

`try_files` нужен SPA: без него прямой заход на `/works/123` даст 404. Фронт и API на одном origin, поэтому CORS не нужен.

## Модель данных

Работа любого из четырёх типов — одна строка `works`: общие поля — колонками, поля своего типа — в `details` (JSONB), а форму `details` держит pydantic-модель типа. Люди в работах лежат отдельной таблицей: по ним ищут, считают и сливают. Все id — `uuid` v7 из Python (`uuid.uuid7()`): они растут по времени, и индекс не фрагментируется.

| Таблица | Поля | Зачем |
| --- | --- | --- |
| `works` | `id`, `type`, `status`, `title`, `title_key`, `year`, `department` → `departments`, `annotation`, `keywords` text\[\], `language`, `access_level`, `consent`, `external_url`, `doi`, `issn`, `details` jsonb, `field_meta` jsonb, `file_key`, `original_file_name`, `related_id` → `works`, `duplicate_of` → `works`, `import_id` → `imports`, `reject_reason`, `search` tsvector, `published_at`, `created_at`, `updated_at`, `created_by` → `users` | Работа любого типа |
| `work_people` | `work_id`, `role` (`author`, `supervisor`, `presenter`), `position`, `person_id` → `people` или NULL, `display_name`, `kind`; PK (`work_id`, `role`, `position`) | Авторы, руководители и докладчики в порядке из работы. `person_id` NULL — нераспознанный автор |
| `work_subjects` | `work_id`, `scheme`, `code` → `classifiers` | Рубрики ГРНТИ, ОЕСР, WoS, ASJC |
| `work_citations` | `work_id`, `source` (`crossref`, `rinc`, …), `count`, `updated_at` | Цитирования по источникам; `citations` в API — максимум из них |
| `materials` | `id`, `work_id`, `name`, `size`, `kind`, `status`, `file_key`, `uploaded_by` → `users`, `uploaded_at`, `decided_by`, `decided_at` | Материалы авторов (раздел «Материалы авторов») |
| `people` | `id`, `kind`, `full_name`, `department` → `departments`, `position`, `academic_degree`, `academic_title`, `orcid`, `affiliation`, `photo_key`, `merged_into` → `people` | Сотрудники, студенты, выпускники, внешние авторы |
| `person_names` | `person_id`, `name`, `exact_key`, `short_key` | Полное ФИО и все варианты написания с ключами сопоставления; `aliases` в API — имена отсюда кроме `full_name` |
| `departments` | `name` PK | Кафедры; ссылки по имени с `ON UPDATE CASCADE` |
| `users` | `id`, `login` unique, `password_hash`, `role`, `person_id` → `people`, `name`, `is_active`, `token_version` | Учётки (раздел «Авторизация и мидлвари») |
| `imports`, `import_items` | поля `Import` и `ImportItem` из контракта; у элемента ещё `n` и `file_key` | Импорт; `stats` считаются по элементам |
| `extraction_results` | `work_id`, `field`, `value`, `confidence` | Сырой ответ воркера (раздел «Статистика») |
| `journals`, `classifiers`, `directions` | раздел «Справочники и начальные данные» | Справочники |

- **Почему одна `works` с JSONB.** У типов около 15 общих полей, по которым фильтрует каталог, и от 5 до 12 своих. Форму своих держат `StudentDetails`, `PublicationDetails` и `TalkDetails` — поля `StudentWork`, `Publication` и `Talk` из контракта без общих. Таблица на тип дала бы JOIN на каждый список и четыре миграции на одно новое общее поле.
- **Колонками вынесено то, что нужно вне JSON:** `doi` — для поиска дубля и обновления цитирований, `issn` — для списков журнала, `consent` — для проверки доступа. Из `file_key` следует `hasFile`.
- **Ключи сопоставления считает Python при записи** (`shared/names.py` — перенос `src/mocks/names.ts`). `title_key` — название в нижнем регистре без знаков: по (`type`, `title_key`, `year`) импорт ищет дубль. `exact_key` — ФИО без пробелов, точек и запятых, `ё` → `е`: точное совпадение «Иванов И.И.» и «Иванов И. И.». `short_key` — транслит фамилии и первая буква имени (`ivanov:i`) для подсказок по нераспознанным авторам.
- **Связь публикация ↔ доклад симметрична:** `related_id` пишется у обеих работ в одной транзакции, старая пара при этом разрывается (`syncRelated` в моках).
- **Слияние людей** — одна транзакция: `work_people.person_id` и `users.person_id` переводятся на основного, имена второго уходят в `person_names` основного, пустые поля основного заполняются из второго, у второго ставится `merged_into`, а `search` его работ пересчитывается. Запрос по старому id отдаёт основной профиль. Отмены нет, как и в интерфейсе.
- **Вычисляемое не храним:** `view`, `errors`, `issues`, `actions`, счётчики, метрики и `stats` импорта собираются при чтении. Исключение — `search`: его сервис пересчитывает при каждой записи (раздел «Поиск и фасеты»).
- **Работы не удаляются:** в контракте нет DELETE, снятая или отклонённая работа остаётся строкой со статусом.
- **Ограничения — в базе:** CHECK на перечисления (`type`, `status`, `access_level`, `role`, `kind`), FK со всеми ссылками, CHECK `access_level <> 'full' OR consent OR type IN ('publication', 'talk')` — открытый текст студенческой работы без согласия не сохранится даже с ошибкой в коде.
- **Индексы:** `works (status, type, year)`, GIN по `works.search`, `works (type, title_key, year)`, `works (lower(doi))`, `work_people (person_id)`, `work_people (display_name) WHERE person_id IS NULL` — для списка нераспознанных, `work_subjects (scheme, code)`, `person_names (exact_key)`, `person_names (short_key)`, `materials (work_id)`. Остальные — по `EXPLAIN`, когда запрос покажет себя на реальных данных.

## Поиск и фасеты

Работы ищем полнотекстовым поиском PostgreSQL с русской морфологией, людей — по началам слов, а фасеты считаем дизъюнктивно. Отдельный поисковый движок (Elasticsearch, Meilisearch) не нужен: на десятках тысяч работ PostgreSQL отвечает за миллисекунды, а ещё один сервис пришлось бы синхронизировать с базой. Эталон семантики — `catalog`, `facets` и `adminPeople` в `src/mocks/logic.ts`.

**Работы.** `works.search` сервис пересчитывает при каждой записи работы, а также при переименовании, слиянии и привязке человека — для всех его работ. Веса взяты из моков (3, 2, 2, 1, 1):

```sql
setweight(to_tsvector('russian', :title), 'A') ||
setweight(to_tsvector('russian', :keywords_and_people), 'B') ||  -- ФИО как в работе и полные из people
setweight(to_tsvector('russian', :annotation), 'C') ||
setweight(to_tsvector('russian', :venue), 'D')               -- журнал, конференция или направление
```

- Конфигурация `russian` приводит русские слова к основе, а латиницу — английским стеммером, так что англоязычные названия тоже находятся по словоформам.
- `ё` → `е` заменяем в Python и в тексте, и в запросе: сам PostgreSQL их не приравнивает.
- Запрос — `websearch_to_tsquery('russian', :q)`: понимает кавычки, `or` и минус, а на любом вводе возвращает запрос без ошибки синтаксиса.
- Сортировка: `relevance` (по умолчанию при `q`) — `ts_rank_cd(search, query)`, при равенстве новее выше; `new` — год, затем `published_at`; `title` — название в `COLLATE "ru-RU-x-icu"`.
- Видимость — только через `published()`: `status = 'published' AND access_level <> 'hidden'`. `total` — `count(*) OVER ()` в том же запросе, `pageSize` — до 100 в каталоге и до 200 в админке.
- В админке `q` ищет ещё и по имени файла импорта (`original_file_name`, `icontains`). Сортировка `problems` считает проверки в Python по всем подходящим черновикам. `ponytail`: при тысячах черновиков число замечаний придётся хранить колонкой.
- Опечатки поиск работ не прощает. Если понадобится, вторым проходом при пустой выдаче добавим `pg_trgm` по названию.

**Люди.** «Иванов И. И.» находит «Иванов Иван Иванович», если каждое слово запроса — начало какого-то слова имени. Это префиксный `tsquery` по конфигурации `simple` над всеми вариантами имени в `person_names`. Индекс — GIN по тому же выражению. Один запрос обслуживает `/admin/people?q`, `/people?q` и подсказки в редакторе авторов.

```python
tokens = re.findall(r"\w+", q.lower().replace("ё", "е"))
query = " & ".join(f"{t}:*" for t in tokens)  # только буквы и цифры: синтаксис tsquery им не сломать
```

```sql
SELECT DISTINCT person_id FROM person_names
WHERE to_tsvector('simple', replace(lower(name), 'ё', 'е')) @@ to_tsquery('simple', :query)
```

**Фасеты.** Внутри фасета выбор соединяется через ИЛИ, между фасетами — через И. Счётчики фасета `k` считаются по выдаче со всеми фильтрами, кроме `k`: иначе выбранный вариант обнулил бы соседние. Выбранное значение без совпадений остаётся с нулём, чтобы его можно было снять. Набор фасетов вкладки — как `TAB_FILTERS` в моках, а фасет `type` (счётчики вкладок) считается по общим фильтрам вкладки «Все».

| Фасет | Откуда значения |
| --- | --- |
| `year`, `department` | Колонки `works` |
| `author`, `supervisor` | `work_people` с ролью `author` или `presenter` — или `supervisor`, только сотрудники |
| `level`, `direction`, `discipline`, `pubKind`, `venue`, `confLevel`, `talkKind`, `format`, `courseKind` | Поля `details`; у `courseKind` по умолчанию `work` |
| `indexing` | Массив `details->'indexing'` |
| `journalList` | `journals.lists` по `works.issn` |
| `grnti`, `oecd`, `wos`, `asjc` | `work_subjects` |

Подписи значений — из констант сервиса и справочников (`classifiers`, `directions`, короткие ФИО из `people`). Каждый фасет — отдельный короткий `GROUP BY` в одной читающей транзакции, до 15 запросов на страницу каталога. `ponytail`: если упрётся в время, считать фасеты из материализованного представления по опубликованным работам.

## Импорт и шина событий

Шина нужна одной задаче — разбору архивов ВКР и курсовых: ИИ тратит на файл секунды или минуты, в HTTP-запрос это не уложить. Таблицы публикаций и докладов import\_service разбирает синхронно и сразу ставит `done`, как в моках.

Архив проходит четыре шага:

1. `POST /admin/imports`: import\_service потоком кладёт архив в MinIO и распаковывает PDF в `imports/{import_id}/items/{n}.pdf`. Он создаёт `Import(processing)` и по `ImportItem(pending)` на каждый файл, а после коммита публикует `import_item.created` на каждый файл.
2. extraction\_worker берёт PDF из MinIO, заполняет карточку (раздел «ИИ-заполнение карточек») и публикует `import_item.extracted` с полями или ошибкой.
3. import\_service создаёт черновик: ищет дубль по названию и году, сопоставляет авторов и сохраняет сырой результат воркера в `extraction_results`. Когда готовы все элементы, импорт переходит в `done`.
4. Фронт видит прогресс, опрашивая `GET /admin/imports/:id` раз в 3 секунды.

| Событие | Публикует | Слушает | Payload |
| --- | --- | --- | --- |
| `import_item.created` | import\_service | extraction\_worker | `item_id`, `file_key`, `work_type` |
| `import_item.extracted` | extraction\_worker | import\_service | `item_id` и либо `fields` + `field_meta`, либо `error` |

Routing key — это факт в домене, а не адресат, как в каркасе. Очередь у сервиса называется его именем (`extraction_worker`, `import_service`). Публикация работы событий не требует: admin меняет статус, и catalog сразу читает его из той же базы. События вроде `work.published` добавим, когда появится подписчик.

Правила:

- **Идемпотентность.** Если item уже не `pending`, сообщение получает ack без действий, и второй черновик не появится.
- **Ошибка ИИ на файле — не dead letter.** Это `item.status = error` с человеческим текстом: модератор должен её увидеть. В `dead_letters` уходят только битые конверты.
- **LLM-сервер недоступен** — временная ошибка, под которую каркас откладывал повторы. Повтор идёт через очередь с TTL и dead-letter обратно, не больше 3 попыток по `x-death`, потом `error`.
- **Параллельность воркера.** `channel.set_qos(prefetch_count=N)`, где N — сколько параллельных запросов тянет LLM-сервер (для vLLM порядка 4–8).
- **Распаковка zip — граница доверия.** Проверять пути (zip slip, `../` в именах) и суммарный размер после распаковки.

## Выгрузка работ

Модератор выгружает работы таблицей (xlsx или csv) с теми же фильтрами, что в списке «Все работы», а при необходимости — zip вместе с PDF. admin\_service отдаёт всё потоком, без фоновых задач.

| Эндпоинт | Что отдаёт |
| --- | --- |
| `GET /api/admin/exports/works?type&year&status&department&q&format=xlsx\|csv` | Таблицу работ по фильтрам. Колонки — как в шаблоне импорта этого типа, плюс `id`, статус, уровень доступа и ссылка на карточку |
| `GET /api/admin/exports/works.zip?…` (те же фильтры) | `works.xlsx` и PDF в `files/{id}.pdf` |
| `GET /api/admin/exports/people?format=xlsx\|csv` | Людей: ФИО, варианты написания, кафедра, должность, ORCID, число работ |

Все эндпоинты — за `require_moderator`. Названия колонок совпадают с шаблоном импорта, чтобы модераторам не учить второй формат. Обратно таблица не импортируется: импорт создаёт новые черновики. Полная «переносимая» выгрузка всей базы не нужна: это делает бэкап (раздел «Бэкапы»).

- **xlsx** пишет openpyxl в режиме `write_only`: строка за строкой, память не растёт с числом работ.
- **csv** — stdlib `csv`, кодировка `utf-8-sig` и разделитель `;`. Без BOM русский Excel покажет кракозябры, а запятую в русской локали он не считает разделителем.
- **zip** собирает stdlib `zipfile`: он умеет писать в поток без перемотки. PDF ложатся с `ZIP_STORED` (они уже сжаты) и читаются из MinIO кусками, так что архив целиком нигде не лежит.
- **Имя файла** — `Content-Disposition: attachment; filename*=UTF-8''работы-2026-10-12.xlsx`; фронтовый `download()` уже его читает.
- **nginx** — `proxy_buffering off` для `/api/admin/exports/`, иначе большой zip сначала ляжет во временный файл nginx.
- **Фронт** качает таблицу через `download()`, а zip — обычной ссылкой. Тогда браузер пишет файл на диск потоком, а blob держал бы гигабайты в памяти. Кука уходит сама, запрос same-origin.
- **Аудит.** В выгрузках персональные данные студентов, поэтому каждая выгрузка пишется в лог: кто, фильтры, сколько строк и файлов.

## ИИ-заполнение карточек

Карточку ВКР заполняет локальная модель в extraction\_worker. Всё, что берётся регуляркой, берётся без LLM, а confidence считает сервер, а не модель.

**Текст.** pypdf, только титульник, первые 2–3 страницы и страница «Реферат» — 3–5 тысяч токенов вместо 80 страниц. Пустой текст означает скан: item получает `error` «Скан без текстового слоя». OCR (pypdfium2 и Tesseract с `rus`) добавим, если сканов окажется много.

**Регулярки**, confidence 0.95:

| Поле | Где искать |
| --- | --- |
| Код направления | `\b\d{2}\.\d{2}\.\d{2}\b` на титульнике |
| Год | строка «Москва 2026» внизу титульника |
| Страницы | «содержит 68 с.» в реферате |
| Ключевые слова | строка после «Ключевые слова:» или список капсом в реферате |
| Уровень | слова «бакалавр», «магистр», «специалист» |

**LLM** заполняет остальное: название, ФИО авторов и руководителей, кафедру, профиль, аннотацию. Чем меньше полей у модели, тем она быстрее и тем реже ошибается. Ответ ограничен JSON-схемой через `response_format: json_schema`: сервер не даёт модели выдать невалидный JSON. `temperature: 0`.

**Модели.** Выбираем замером на наших файлах; цифры качества в публикациях в основном от самих разработчиков.

| Модель | Почему | Лицензия |
| --- | --- | --- |
| GigaChat3.1-10B-A1.8B (Lightning) | MoE с 1.8B активных параметров — самая быстрая. Обучена на русском, токенизатор экономнее на кириллице (3.74 символа на токен против 2.57 у Qwen2.5-7B). Есть GGUF | MIT |
| Qwen3.5-9B | Сильная универсальная модель марта 2026, лучше всех поддержана в vLLM и llama.cpp | Apache-2.0 |

Начинаем с GigaChat Lightning; если не дотянет по точности — Qwen3.5-9B. Режим рассуждений, если он есть у модели, выключаем: для извлечения он только тратит время.

**Сервер.** При NVIDIA GPU — vLLM: OpenAI-совместимый API, ограниченная генерация по схеме через XGrammar, батчинг. Без GPU — llama.cpp server с GGUF Q4, медленнее, но для пачки ВКР раз в семестр приемлемо. Модель на \~10B в bf16 занимает около 20 ГБ VRAM, в 4 битах — около 6–7 ГБ плюс KV-кэш. Воркер ходит в `/v1/chat/completions` через httpx: протокол одинаковый у vLLM, llama.cpp и Ollama, сервер меняется без правки кода. Адрес, модель и таймаут — в `LLMConfig` (`LLM_URL`, `LLM_MODEL`, `LLM_TIMEOUT_SECONDS`).

```python
class ExtractedCard(BaseModel):
    """Поля карточки, которые не достаются регулярками."""

    title: str | None
    authors: list[str]
    supervisors: list[str]
    department: str | None
    profile: str | None
    annotation: str | None


async def extract_card(text: str) -> ExtractedCard:
    """Заполняет карточку по тексту титульника и реферата."""
    response = await http.post(
        f"{llm_config.url}/v1/chat/completions",
        json={
            "model": llm_config.model,
            "temperature": 0,
            "messages": [{"role": "system", "content": EXTRACT_PROMPT}, {"role": "user", "content": text}],
            "response_format": {
                "type": "json_schema",
                "json_schema": {"name": "card", "schema": ExtractedCard.model_json_schema()},
            },
        },
        timeout=llm_config.timeout_seconds,
    )
    response.raise_for_status()
    return ExtractedCard.model_validate_json(response.json()["choices"][0]["message"]["content"])
```

**Confidence.** Модель про свою уверенность не спрашиваем: она почти всегда отвечает «0.95». Считаем сами:

| Проверка | Confidence |
| --- | --- |
| Значение нашлось регуляркой | 0.95 |
| Значение LLM есть в исходном тексте после нормализации пробелов, регистра и «ё» | 0.85 |
| Плюс подтвердилось по базе: руководитель найден среди сотрудников, кафедра есть в списке, код есть в справочнике направлений | 0.95 |
| Значения нет в тексте — вероятно, выдумано | 0.4 |

Порог 0.7 даёт `lowConfidence`, и модератор видит поле подсвеченным. В ответе это `fieldMeta: {source: "ai", confidence}` из контракта. Если понадобится точнее, vLLM отдаёт `logprobs`: среднюю вероятность токенов значения можно подмешать в confidence.

**Ошибки.** Таймаут на элемент — 120 секунд; сработал — item получает `error` «ИИ не ответил», а в лог уходят подробности по стадиям (раздел «Ошибки и логи»).

**Замер точности.** На 20–30 реальных ВКР заполняем карточки вручную. Скрипт прогоняет обе модели и считает точность по каждому полю и время на файл: по нему выбираем модель и проверяем порог. В проде точность видна на дашборде «ИИ» по таблице `extraction_results`.

## Файлы в MinIO

Все файлы лежат в MinIO и доступны через `shared/storage.py` на aioboto3. Общего диска у сервисов нет, поэтому они могут жить на разных хостах. Ссылка на файл — presigned URL; это и есть `FileLink {url, expiresAt}` из контракта.

| Ключ | Пишет | Читает |
| --- | --- | --- |
| `imports/{import_id}/archive.zip` | import\_service | — |
| `imports/{import_id}/items/{n}.pdf` | import\_service при распаковке | extraction\_worker |
| `works/{work_id}/{uuid}.pdf` | admin\_service (загрузка в редакторе), import\_service (черновик из архива) | catalog и admin через presign |
| works/{work\_id}/materials/{uuid} | admin\_service (материалы авторов) | catalog и admin через presign |
| `people/{id}/{uuid}.jpg` | admin\_service | все, публично |

- **Кто выдаёт ссылки.** catalog — только на опубликованную работу с `accessLevel = full`, иначе 404. admin — на любую. Ссылка живёт 1 час (`expiresAt`).
- **Хост в подписи.** Сервисы ходят в `http://minio:9000`, а браузер такого хоста не знает. Подпись SigV4 включает хост и путь, поэтому presign делает второй клиент с `S3_PUBLIC_URL` = `https://files.<домен>` (в dev — `https://files.localhost`). nginx проксирует этот домен в MinIO без изменения пути, и подпись сходится. Presign считается локально, этот клиент никуда не подключается.
- **Снаружи MinIO только читается.** Порт 9000 наружу не публикуется. На `files.<домен>` nginx пропускает только GET и HEAD и закрывает `/minio/` — health, метрики и admin API.
- **PDF в iframe редактора.** Объект кладём с `ContentType=application/pdf`, presign делаем с `ResponseContentDisposition=inline; filename*=UTF-8''…`. Иначе вместо показа начнётся скачивание.
- **Фото людей.** Presign на каждый запрос меняет URL, и кэш браузера не работает. Поэтому `people/*` открыт на анонимное чтение, а `photoUrl` постоянный. Политика — свой JSON с одним `s3:GetObject`: стандартный `mc anonymous set download` разрешает ещё и листинг префикса. `{uuid}` в ключе закрывает перебор по id и даёт новому фото новый URL, так что кэш не показывает старое.
- **Большие архивы.** Идут через import\_service потоком в MinIO: `upload_fileobj` сам режет на multipart, а лимиты проверяет сервер. Прямой presigned PUT из браузера понадобится, только если архивы станут огромными, и тогда изменится контракт фронта.
- **Бакет и доступы создаёт `minio-init`** — одноразовый сервис compose под root-учёткой MinIO: бакет, версионирование, lifecycle, анонимное чтение `people/*` и два пользователя: `app-rw` (admin, import) и `app-ro` (catalog, воркер). Root-ключ сервисам не выдаётся.
- **CORS на MinIO не нужен:** фронт открывает `FileLink` навигацией и в iframe, а не через `fetch`.

## Материалы авторов

Автор прикладывает к своей публикации или докладу файлы (текст, слайды, данные), модератор принимает или отклоняет их, а принятые появляются на странице работы. Вся логика — в admin\_service, эталон — обработчики `/my/*` и `/admin/works/:id/materials/*` в моках.

1. **Автор загружает:** `POST /api/my/works/:id/materials` (multipart: `file`, `kind`). Работа должна быть его (`person_id` среди авторов или докладчиков, иначе 404) и иметь тип `publication` или `talk` (иначе 400). Файл проверяется по `upload-limits.material` — `.pdf`, `.pptx`, `.docx`, `.zip` до 50 МБ — и по сигнатуре. Объект ложится в `works/{work_id}/materials/{uuid}`, строка `materials` создаётся со статусом `pending`, ответ — 201 с `Material`.
2. **Модератор решает.** Ожидающие материалы видны в `GET /admin/summary` (`pendingMaterials`) и в `materials` работы. Файл любого статуса открывается через `GET /admin/works/:id/materials/:mid`, решение — `POST /admin/works/:id/materials/:mid {status}` со статусом `approved` или `rejected`. Решение записывается в `decided_by` и `decided_at` и в аудит-лог.
3. **Публично.** Принятые материалы попадают в `view.materials`. `GET /works/:id/materials/:mid` выдаёт ссылку только на `approved` у видимой работы, иначе 404.
4. **Удаление.** Автор удаляет свой материал только в статусе `pending` (`DELETE /my/works/:id/materials/:mid`, иначе 409). Удаляются и строка, и объект; старая версия объекта в MinIO хранится 30 дней.

- `GET /my/works` отдаёт работы, где автор среди авторов или докладчиков, кроме `rejected`. `canUpload` есть у публикаций и докладов, `public` — видна ли работа в каталоге. Автор видит и черновики со своим именем, но их поля не меняет.
- Content-Type у PDF — `application/pdf`, у остальных — `application/octet-stream`. Ссылка на материал всегда с `attachment` и исходным именем: материал скачивают, а не смотрят во вкладке.
- Отклонённый материал остаётся у автора со статусом `rejected`. Исправленная версия загружается как новый материал.
- В nginx для пути загрузки материала — `client_max_body_size 50m` и `auth_request` (раздел «Сервисы и маршрутизация»).

## Авторизация и мидлвари

Сессия — JWT в HttpOnly-куке. Мидлварь никогда не отвечает 401 сама: права проверяют зависимости роутеров.

- **Вход.** `POST /auth/login` проверяет пароль (argon2) и кладёт JWT в куку `__Host-session`: `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`, `max_age` равен TTL — 8 часов. Префикс `__Host-` запрещает атрибут `Domain`, поэтому страница на другом поддомене вуза не подложит свою куку. По http браузер такую куку не примет, поэтому имя берётся из `AuthConfig`: в dev — `session_token` без `Secure`.
- **Без утечки логинов.** Если логина нет, пароль всё равно сверяется с фиктивным хэшем, и ответ тот же 401: по времени ответа не понять, есть ли пользователь. После успешного входа `check_needs_rehash` пересчитывает хэш, если параметры argon2 поменялись.
- **Выход и отзыв.** `POST /auth/logout` стирает куку и увеличивает `users.token_version` — гаснут все сессии пользователя. Блокировка (`is_active = false`) и смена роли действуют сразу: зависимости читают пользователя из базы по первичному ключу.
- **Подпись асимметричная — EdDSA (Ed25519).** auth\_service подписывает токен приватным ключом, admin и import проверяют подпись публичным и в auth\_service не ходят. Приватный ключ есть только у auth\_service: взлом воркера или другого сервиса не даёт выпустить себе токен. Токен не шифруется — секретов в нём нет, только подпись.
- **Claims:** `sub` (id пользователя строкой — pyjwt требует строку), `ver` (`token_version`), `name`, `iat`, `exp`. Роли в токене нет: её берут из базы. Список `algorithms` при проверке фиксирован, поэтому токен с `alg: none` или HS256 не пройдёт.
- **Роли** — `moderator`, `admin`, `author`; проверяют зависимости на роутере: `require_moderator` у `/api/admin/*` (admin и import), `require_author` у `/api/my/*` (admin). Автору на `/admin/*` — 403 с `{error: {code: "forbidden", message}}`. Роль `admin` в API пока даёт то же, что `moderator`: единственное, что только для admin, — пользователи и роли, а их меняют командой на сервере, не по HTTP. `require_admin` появится вместе с первым таким эндпоинтом. Слияние людей, bulk и выгрузки остаются у модератора: это его ежедневная работа.
- **Автор видит только своё.** Работа в `/api/my/*` ищется сразу с условием «среди авторов есть `user.person_id`», чужая — 404, как несуществующая. Удалить можно только свой материал в статусе `pending`.
- **Публичное** — всё, что не `/admin` и не `/my`. Невалидный или протухший токен на публичном пути считается анонимом, иначе человек со старой кукой не увидит каталог.
- **Пользователи** — команда на сервере `python -m auth_service.users add|role|block|password <логин>`, пароль читается из stdin; `role`, `block` и `password` увеличивают `token_version`. Первый admin создаётся той же командой, паролей по умолчанию нет. От HTTP-админки пользователей отказались: нет эндпоинта — нечего угонять.
- **Перебор паролей.** `limit_req` в nginx — 5 попыток в минуту с IP. Если перед nginx стоит прокси вуза, нужен `set_real_ip_from`, иначе лимит станет общим на всех. В лог пишем вход (успех и неудача, логин, IP), выход, смену роли и блокировку; неудачный вход — `warning`.
- **Аудит.** Необратимое и массовое — слияние людей, bulk, публикация и снятие, решения по материалам — пишется в лог одной строкой: кто, что, id. Выгрузки уже пишутся (раздел «Выгрузка работ»).

Ключи — пара Ed25519 в файлах. В контейнеры они попадают через `secrets` compose, а не через `.env`: приватный только в auth\_service, публичный — в auth, admin и import. catalog и воркеру ключи не нужны. Папка `secrets/` — в `.gitignore`.

```bash
openssl pkey -in secrets/jwt_private.pem -pubout -out secrets/jwt_public.pem
```

Ротация — заменить пару и перезапустить сервисы: все перелогинятся, при TTL 8 часов и десятке модераторов это приемлемо. Если понадобится менять ключ без разлогина, добавим `kid` в заголовок токена и несколько публичных ключей.

`shared/auth.py`:

```python
@cache
def _key(name: str) -> bytes:
    return (Path("/run/secrets") / name).read_bytes()


def issue_token(user: User) -> str:
    """Только auth_service: у остальных нет приватного ключа."""
    now = datetime.now(UTC)
    claims = {"sub": str(user.id), "ver": user.token_version, "name": user.name, "iat": now, "exp": now + auth_config.ttl}
    return jwt.encode(claims, _key("jwt_private"), algorithm="EdDSA")


def read_token(token: str) -> dict | None:
    """None — токен битый, чужой или протух: на публичном пути это аноним."""
    try:
        return jwt.decode(token, _key("jwt_public"), algorithms=["EdDSA"], options={"require": ["sub", "ver", "exp"]})
    except jwt.InvalidTokenError:
        return None


async def current_user(ctx=Depends(current_context), uow=Depends(uow_ro_factory)) -> User:
    user = await uow.users.get(ctx.user_id) if ctx.user_id else None
    if user is None or not user.is_active or user.token_version != ctx.token_version:
        raise HTTPException(401, "Нужен вход")
    return user


async def require_moderator(user: User = Depends(current_user)) -> User:
    if user.role not in ("moderator", "admin"):
        raise HTTPException(403, "Недостаточно прав")
    return user


async def require_author(user: User = Depends(current_user)) -> User:
    if user.role != "author" or user.person_id is None:
        raise HTTPException(403, "Недостаточно прав")
    return user
```

Роутер без зависимости откроет `/api/admin/*` или `/api/my/*` всем. Тест ловит это в CI:

```python
@pytest.mark.parametrize(("app", "prefix", "guard"), [

```

| Мидлварь | Что делает | Где |
| --- | --- | --- |
| `RequestContextMiddleware` | Берёт `trace_id` из `X-Request-ID`, кладёт в contextvars и возвращает в ответе. Пишет одну JSON-строку access-лога. Ловит любое необработанное исключение (раздел «Ошибки и логи») | все HTTP-сервисы |
| `AuthMiddleware` | Читает куку, проверяет подпись через `read_token` и дописывает `user_id` и `token_version` в тот же объект контекста, не в новый `use_context` | auth, admin, import |
| `OriginCheckMiddleware` | Защита от CSRF: POST, PUT, PATCH и DELETE с чужим `Origin` получают 403; без `Origin` решает `Sec-Fetch-Site` | auth, admin, import |

catalog обходится одной `RequestContextMiddleware`: он только читает, и пользователь ему не нужен. У extraction\_worker HTTP-мидлварей нет, контекст он берёт из конверта через `use_context`. Последний `add_middleware` выполняется первым:

```python
app.add_middleware(AuthMiddleware)            # 3
app.add_middleware(OriginCheckMiddleware)     # 2
app.add_middleware(RequestContextMiddleware)  # 1 — снаружи: в лог с trace_id попадают и отказы
```

Почему нужен Origin-check: `SameSite=Lax` защищает от чужого *site*, но не от чужого *origin*. Все поддомены вуза считаются одним site, и страница на любом студенческом поддомене может отправить POST на `/api/admin/works/bulk` с кукой модератора.

```python
UNSAFE_METHODS = frozenset({"POST", "PUT", "PATCH", "DELETE"})
SAME_SITE_FETCH = frozenset({"same-origin", "none"})


class OriginCheckMiddleware:
    """Отклоняет изменяющие запросы с чужим Origin: CSRF-защита для куки."""

    def __init__(self, app: ASGIApp) -> None:
        self.app = app

    async def __call__(self, scope: Scope, receive: Receive, send: Send) -> None:
        if scope["type"] == "http" and scope["method"] in UNSAFE_METHODS:
            headers = Headers(scope=scope)
            origin = headers.get("origin")
            if origin is not None:
                foreign = origin not in auth_config.allowed_origins
            else:
                # Origin вырезан (расширение, прокси): браузер всё равно шлёт Sec-Fetch-Site; нет и его — не браузер (curl, тесты)
                foreign = headers.get("sec-fetch-site", "same-origin") not in SAME_SITE_FETCH
            if foreign:
                response = JSONResponse({"error": {"code": "bad_origin", "message": "Запрос с чужого сайта"}}, status_code=403)
                await response(scope, receive, send)
                return
        await self.app(scope, receive, send)
```

`AUTH_ALLOWED_ORIGINS` — домен сайта; в dev добавить `http://localhost:5173`, потому что Vite-прокси передаёт `Origin` браузера как есть.

Не мидлвари: `CORSMiddleware` из каркаса выкидываем (один origin через nginx, в dev — Vite-прокси). Сжатие, лимит тела и rate limit на вход делает nginx: `gzip`, `client_max_body_size`, `limit_req`. Лимиты по типам файлов проверяет сам сервис по `upload-limits`.

## Безопасность

Главные угрозы — соседний поддомен вуза и чужие файлы: PDF и таблицы приходят от студентов. Поэтому чужой контент и Grafana живут на своих доменах, у каждого сервиса только свои ключи и права, а любой файл считается враждебным, пока не проверен.

**Домены.** Три имени на одном nginx, сертификат на все три:

| Домен | Что там | Зачем отдельно |
| --- | --- | --- |
| `<домен>` | Фронт и `/api` | Один origin: CORS не нужен, кука `__Host-session` живёт только здесь |
| `files.<домен>` | MinIO: presigned-ссылки и фото, только GET | PDF, материалы и фото загружены людьми; на origin сайта они ничего не исполнят |
| `stats.<домен>` | Grafana, только из `STATS_ALLOW` | XSS в Grafana не достанет API, кука сайта туда не уходит |

API от фронта на отдельный домен не выносим. Фронт — единственный клиент API и держит сессию, поэтому XSS во фронте дойдёт до API с любого домена. Разделение добавило бы CORS с `credentials`, preflight перед каждым POST и PATCH и новый класс ошибок конфигурации, а защиты не прибавило: изоляция нужна там, где чужой код и чужие файлы.

**Секреты и права.** В `.env` — только несекретное: версии, домен, модель. Секреты — файлы в `secrets/` (папка в `.gitignore`); каждый сервис получает только свои через `secrets` compose, а pydantic-settings читает их из `/run/secrets` (`secrets_dir`). Взлом одного сервиса не даёт ключей остальных.

| Сервис | Роль в базе | MinIO | Ещё |
| --- | --- | --- | --- |
| auth\_service | `auth`: только `users` | — | приватный и публичный ключ JWT |
| catalog\_service | `catalog`: SELECT, без `users` | `app-ro` | — |
| admin\_service | `writer`: всё, кроме `users`; из `users` — SELECT `id`, `role`, `is_active`, `token_version`, `person_id` | `app-rw` | публичный ключ JWT |
| import\_service | `writer` | `app-rw` | RabbitMQ, публичный ключ JWT |
| extraction\_worker | — | `app-ro` | RabbitMQ |
| migrations | `app` — владелец схемы, создаёт остальные роли | — | пароли ролей |
| minio, minio-init | — | root | — |

Роли и права создаёт миграция; пароли она читает из секретов, в коде их нет. `ALTER DEFAULT PRIVILEGES` выдаёт права на новые таблицы сам, `users` настраивается отдельно.

**Чужие файлы.**

- **zip.** Не больше 1000 файлов и 2 ГБ после распаковки; считаем реально прочитанные байты, а не `file_size` из заголовка. Берём только `*.pdf`, вложенные архивы и ссылки пропускаем. Имена из архива в ключи не попадают: ключ — `{n}.pdf`.
- **PDF.** Файл должен начинаться с `%PDF-`, иначе item получает error. pypdf работает в подпроцессе с таймаутом 60 секунд: зависший разбор убивается, а не вешает воркер, потому что asyncio-таймаут синхронный код не прерывает. У контейнера воркера `mem_limit`.
- **Файл роняет воркер.** Очередь воркера — quorum, RabbitMQ считает доставки в `x-delivery-count`. На третьей доставке item сразу получает error «Файл не удалось разобрать»: иначе такой файл крутился бы вечно.
- **xlsx.** openpyxl в режиме `read_only`, рядом установлен `defusedxml` (PSF), openpyxl подхватывает его сам. xlsx — тоже zip, лимит размера как у таблиц.
- **Загрузки в редакторе и от авторов.** Тип определяем по сигнатуре, `ContentType` ставит сервер. PDF — `application/pdf`; остальные материалы — `application/octet-stream` с `Content-Disposition: attachment`, поэтому HTML из материала не откроется как страница. Фото Pillow (MIT-CMU) перекодирует в JPEG и заодно срезает EXIF с координатами. SVG не принимаем.
- **Ссылки в данных.** `externalUrl` и другие URL — только `http` и `https` (`HttpUrl` в pydantic): фронт рендерит их в `<a href>`, и `javascript:` из импорта стал бы XSS.
- **LLM.** Скрытый текст в PDF может подсказать модели нужные значения, и они получат высокий confidence. Поэтому черновик из ИИ никогда не публикуется без модератора, у полей `ExtractedCard` есть `max_length`, а в запросе — `max_tokens`. Модель закрепляем `--revision`, `--trust-remote-code` не включаем, порт vLLM наружу не открыт.

**Персональные данные в логах.** Loki хранит логи 30 дней: `retention_period: 720h` и включённый compactor, по умолчанию Loki не удаляет ничего. Консьюмер шины пишет payload без `fields`: там ФИО и аннотации.

**Цепочка поставок.**

- Зависимости Python — `pip-compile --generate-hashes`, установка с `--require-hashes`; в CI `pip-audit` и `npm audit` (раздел «Инфраструктура»).
- MinIO с октября 2025 года публикует community-версию только исходниками, и закреплённый `minio/minio` исправлений уже не получит. Образ — `cgr.dev/chainguard/minio` по digest или собранный из исходников; так же для `mc`.
- Контейнеры сервисов работают не от root: `USER` в `Dockerfile.base`.

**XSS** закрыта шестью слоями, и ни один не держит всё в одиночку:

1. React экранирует весь текст. `dangerouslySetInnerHTML`, `innerHTML` и `eval` во фронте нет — проверено по коду.
2. React 19 подменяет `javascript:` в `href` и `src` заглушкой, а бэк принимает в URL-полях только `http` и `https`. Там, где фронт переходит по ссылке кодом в обход React (открытие presigned-ссылки и редирект после входа), проходят только http(s) и пути своего сайта: `src/lib/url.ts` с тестом.
3. CSP без `'unsafe-inline'` и `'unsafe-eval'` для скриптов: даже если HTML просочится, inline-скрипт и `onerror=` не выполнятся.
4. API отдаёт только JSON с `nosniff`, и браузер не отрисует ответ как страницу. `HTMLResponse` с данными не используем.
5. Пользовательские файлы и Grafana — на других origin.
6. Кука `HttpOnly`: украсть сессию XSS не сможет, хотя действовать от имени пользователя смогла бы — поэтому главные слои тут 1–3.

Поля работ — простой текст: HTML и Markdown в аннотациях не поддерживаем. Если понадобится разметка, чистим её на сервере при сохранении (`nh3`, MIT).

**SQL-инъекции.**

- Все запросы — SQLAlchemy с привязанными параметрами. asyncpg передаёт значения отдельно от текста запроса, и значение не может стать частью SQL.
- `text()` — только с `:param`. f-строки и `.format()` в SQL ловит ruff: в `pyproject.toml` включена группа `S` (flake8-bandit), правило `S608`.
- Имена колонок и направление сортировки из запроса не подставляются: `sort: Literal["year", "title", "problems"]` и словарь в колонки SQLAlchemy. Чужое значение получает 422 от FastAPI.
- `LIKE` — через `icontains(q, autoescape=True)`: `%` и `_` из запроса ищутся буквально, а не как шаблон.
- Даже удачная инъекция в catalog упрётся в роль `catalog`: только SELECT и без `users`.
- Произвольный SQL есть только в Grafana, и это замысел; его держит роль `grafana_ro`.

**Остальные типовые атаки:**

| Атака | Чем закрыта |
| --- | --- |
| CSRF | Origin-check с запасным `Sec-Fetch-Site`, `SameSite=Lax` |
| Кликджекинг | `frame-ancestors 'none'` |
| Чужие данные (IDOR) | catalog берёт работы только через `published()` репозитория — одно место для фильтра «опубликовано». Тест обходит публичные эндпоинты и проверяет, что черновик нигде не виден. Автор видит только работы со своим `person_id`, чужое — 404 |
| Mass assignment | Схемы записи отдельные, с `extra="forbid"`. `status`, `fieldMeta`, `id`, статус и владельца материала ставит сервер; ORM-объект не заполняется из `model_dump()` целиком |
| Формулы в выгрузках | Название «=HYPERLINK(…)» из импорта стало бы живой формулой в Excel модератора. В csv такие значения получают префикс `'`, в xlsx ячейка принудительно строковая (код ниже) |
| Open redirect | После входа — только путь своего сайта; бэк на внешние адреса не редиректит |
| SSRF | Сервер ходит только в Crossref, MinIO и LLM по адресам из конфига. DOI проверяется регуляркой `^10\.\d{4,9}/\S+$` и кодируется `quote(doi, safe="")`; httpx не следует редиректам |
| Path traversal | Ключи MinIO строятся из id и uuid; имя файла от пользователя в путь не попадает |
| Подмена заголовков | Имя файла в `Content-Disposition` — только `filename*=UTF-8''` через `quote()`, перевод строки туда не пройдёт |
| Command injection | Подпроцесс pypdf — `create_subprocess_exec` со списком аргументов, без shell; ловят ruff `S602`–`S605` |
| Десериализация | Сообщения шины — JSON через pydantic; pickle и `yaml.load` не используем |
| XXE, zip-бомбы | `defusedxml` и лимиты zip (выше) |
| DoS запросами | В pydantic: `q` ≤ 200 символов, `pageSize` ≤ 200, `ids` в bulk ≤ 500. `limit_req` на вход и client-errors, лимиты тела в nginx |
| Утечка через ошибки | Клиенту только `{error: {code, message}}`. Swagger наружу не проксируется: он вне `/api` |

Выгрузки пишут ячейки через два хелпера. openpyxl сам делает формулой любую строку, начинающуюся с `=`:

```python
FORMULA_START = ("=", "+", "-", "@", "\t", "\r")


def csv_value(v: object) -> object:
    return "'" + v if isinstance(v, str) and v.startswith(FORMULA_START) else v


def xlsx_cell(ws: Worksheet, v: object) -> WriteOnlyCell:
    cell = WriteOnlyCell(ws, v)
    if cell.data_type == "f":
        cell.data_type = "s"  # «=…» из данных — текст, а не формула
    return cell
```

## Ошибки и логи

Клиент получает только `{error: {code, message}}` и заголовок `X-Request-ID`. Всё остальное — трейсбек, запрос, контекст — уходит в JSON-лог со `trace_id` и собирается в Loki.

| Ошибка | Ответ | Лог |
| --- | --- | --- |
| Доменные (`NotFoundError`, `ConflictError`…) | 404 / 409, `{error: {code, message}}` | warning: code, message, id сущности |
| `RequestValidationError` | 422, `{error: {code: "validation_error", message, fields: [{field: "event.dateEnd", message}]}}` | warning: `exc.errors()` **без ключа `input`**, иначе в лог уйдёт пароль из тела `/auth/login` |
| `HTTPException` | его статус, тот же формат | warning |
| Всё остальное | 500, `{error: {code: "internal", message, traceId}}` | error и traceback |

Необработанное ловим в `RequestContextMiddleware`, а не в `exception_handler(Exception)`. Этот хэндлер выполняет `ServerErrorMiddleware` снаружи всех мидлварей: к этому моменту `use_context` уже сброшен, `trace_id` в лог не попадёт, а ответ будет text/plain.

```python
async def __call__(self, scope: Scope, receive: Receive, send: Send) -> None:
    if scope["type"] != "http":
        await self.app(scope, receive, send)
        return
    trace_id = Headers(scope=scope).get("x-request-id") or uuid4().hex
    ctx = MessageContext(trace_id=trace_id)  # AuthMiddleware дописывает ctx.user_id в этот же объект
    status: int | None = None
    started = time.perf_counter()

    async def send_traced(message: Message) -> None:
        nonlocal status
        if message["type"] == "http.response.start":
            status = message["status"]
            message["headers"] = [*message.get("headers", []), (b"x-request-id", trace_id.encode())]
        await send(message)

    with use_context(ctx):
        try:
            await self.app(scope, receive, send_traced)
        except Exception:
            logger.exception("Необработанная ошибка", extra=request_details(scope))
            if status is not None:
                raise  # ответ уже начат, заменить его нечем
            await error_response(500, "internal", "Внутренняя ошибка сервера")(scope, receive, send_traced)
        finally:
            logger.info("HTTP-запрос", extra={
                "method": scope["method"], "path": scope["path"], "status": status or 500,
                "duration_ms": round((time.perf_counter() - started) * 1000),
            })
```

`request_details(scope)` — method, path, query, шаблон пути `route` (например `/admin/works/{id}`), `path_params`, IP, User-Agent, Content-Length. Роутер дописывает их в тот же `scope`, поэтому снаружи они уже видны. Встроенный access-лог uvicorn выключаем (`--no-access-log`): в нём нет `trace_id`.

Что ещё пишем:

| Где | Что в лог |
| --- | --- |
| Консьюмер шины | type, source, message\_id, очередь, `redelivered`, payload до \~2 КБ без fields (там ФИО и аннотации), traceback и причина ухода в dead letters |
| Публикация в шину | topic и id сущности. Публикация после коммита упала — событие потеряно (осознанный `ponytail` каркаса), в логе это error |
| extraction\_worker | import\_id, item\_id, file\_key, стадия (`s3` / `pdf` / `ai` / `parse`), длительность. При ошибке разбора — сырой ответ модели (обрезанный) и имя модели |
| Crossref, MinIO, LLM-сервер | URL или key, статус, длительность, обрезанное тело на не-2xx. Таймауты — отдельной записью |
| SQL | Текст запроса есть в исключении SQLAlchemy. `create_async_engine(..., hide_parameters=True)`: в параметрах персональные данные |
| Старт и фон | Падение в lifespan (нет базы или RabbitMQ) — `logger.exception` до выхода. `loop.set_exception_handler` для задач без await, `logging.captureWarnings(True)`. Логгеры uvicorn, sqlalchemy и aio\_pika — через тот же JSON-форматтер |
| Браузер | `POST /api/client-errors`: message, stack, url, userAgent, версия сборки, последний `traceId` |

**В лог никогда не пишем:** пароли, куку и `Authorization`, JWT, presigned URL (до истечения это пропуск к файлу), содержимое файлов.

**nginx.** `add_header X-Request-ID $request_id always` — ID есть и у ответов самого nginx (502, 504, 413). Access-лог nginx — в JSON с `$request_id`: если сервис лежит, 502 больше нигде не запишется.

**Loki.** Все сервисы пишут JSON в stdout, логи контейнеров собирает Grafana Alloy и отправляет в Loki; Promtail не берём, он снят с поддержки. Метки — только `service` и `level`. `trace_id` в метки не кладём: Loki индексирует метки, и на поле с бесчисленными значениями индекс разрастается. Вся цепочка одного запроса:

```logql
{service=~".+"} | json | trace_id="3f9a…"
```

Sentry или GlitchTip — другой инструмент. Loki хранит все строки и отвечает на вопрос «что происходило». Sentry группирует одинаковые исключения в проблемы, считает их, шлёт алерты и показывает локальные переменные. Добавим GlitchTip (MIT, совместим с SDK Sentry), если понадобятся алерты; self-hosted Sentry для нас слишком тяжёлый.

## Статистика

Grafana уже стоит под Loki, поэтому для статистики добавляется один сервис — Prometheus, экспортер Postgres и read-only доступ к базе. Собственные метрики в коде сервисов (`prometheus_client`) пока не нужны: HTTP-цифры уже есть в логах.

| Источник | Что даёт | Новый код |
| --- | --- | --- |
| Loki | HTTP из access-лога: запросы в секунду, доля 5xx, p95 по роутам | нет |
| Prometheus | Инфраструктура через встроенные `/metrics`: RabbitMQ (плагин `rabbitmq_prometheus`, порт 15692), MinIO, vLLM, Postgres через `postgres_exporter` | нет |
| PostgreSQL | Бизнес-цифры SQL-запросами прямо в панелях | views в схеме `stats` |

p95 из логов: `quantile_over_time(0.95, {service="catalog"} | json | unwrap duration_ms [5m])`.

| Дашборд | Что на нём |
| --- | --- |
| HTTP | Запросы в секунду и 5xx по сервисам, p95 по роутам |
| Импорт | Сколько файлов ждёт в очереди `extraction_worker`, время на файл и ошибки по стадиям (из логов воркера), dead letters |
| ИИ | Скорость vLLM. Точность в проде: какую долю AI-полей модератор исправил, по каждому полю и по интервалам confidence; отсюда же подбирается порог 0.7 |
| Контент | Публикации по типам и месяцам, очередь черновиков, импорты по неделям, нераспознанные авторы |
| Инфра | Соединения Postgres, очереди RabbitMQ, занятое место в MinIO, GPU |

Для точности ИИ нужен сырой результат воркера: после правки модератора `fieldMeta` становится `manual`, и что предлагала модель, уже не видно. Поэтому выдача воркера ложится в таблицу `extraction_results(work_id, field, value, confidence)`; она пригодится и для отладки.

`monitoring/prometheus.yml`:

```yaml
scrape_configs:
  - {job_name: rabbitmq, static_configs: [{targets: ["rabbitmq:15692"]}]}
  - {job_name: postgres, static_configs: [{targets: ["postgres-exporter:9187"]}]}
  - {job_name: minio, metrics_path: /minio/v2/metrics/cluster, static_configs: [{targets: ["minio:9000"]}]}
  - {job_name: vllm, static_configs: [{targets: ["llm:8000"]}]}
```

Источники данных и дашборды (JSON) хранятся в репозитории в `monitoring/grafana/provisioning/`: настройки как код, а не клики в UI. Паролей в этих файлах нет: datasource берёт пароль `grafana_ro` из секрета через `$__file{/run/secrets/db_grafana}`. Grafana открывается на `https://stats.<домен>/` и только из сети вуза.

Проверить при запуске:

- плагин `rabbitmq_prometheus` может быть выключен в образе — тогда включить через `enabled_plugins`;
- MinIO по умолчанию отдаёт метрики только с токеном: `MINIO_PROMETHEUS_AUTH_TYPE=public`, а наружу они не выходят: порт 9000 не опубликован, а nginx закрывает /minio/ на files.<домен>.

Безопасность:

- Grafana выполняет произвольный SQL из панелей. У неё отдельная роль `grafana_ro` с SELECT только на схему `stats` с views и `statement_timeout = 30s`, чтобы тяжёлая панель не повесила базу. К `users` (хэши паролей) и сырым персональным данным доступа нет. Views и роль создаёт миграция alembic, пароль роли она читает из секрета.
- У postgres\_exporter своя роль `exporter` с `pg_monitor`.
- Grafana живёт на своём домене `stats.<домен>` и пускает только адреса из `STATS_ALLOW` (сеть вуза или VPN). Анонимный доступ выключен, пароль admin — из секрета. На домене сайта Grafana нет: XSS в ней не дотянется до API, а кука сайта туда не уходит.

## Инфраструктура

Всё поднимается одним compose на базовом образе из каркаса: сначала `docker build -f Dockerfile.base -t project-base .`, потом `docker compose up -d --build`. Фронт лежит в `frontend/` того же репозитория и собирается в образ nginx.

| Сервис compose | Образ | Зачем |
| --- | --- | --- |
| `postgres` | postgres:17 | база |
| `rabbitmq` | rabbitmq:4-management | шина |
| `minio` | сборка из minio/ (исходники MinIO и mc) | файлы; minio-init создаёт бакет и доступы |
| `migrations` | project-base | `alembic upgrade head`, завершается с кодом 0 |
| `auth_service`, `catalog_service`, `admin_service`, `import_service`, `extraction_worker` | project-base и код сервиса | приложение |
| `llm` | vllm/vllm-openai или llama.cpp server | модель |
| `nginx` | сборка из `frontend/` | TLS, статика фронта, прокси на сервисы, MinIO и Grafana |
| `loki`, `alloy`, `prometheus`, `postgres-exporter`, `grafana` | официальные образы | логи и статистика |

Community-образы MinIO больше не публикуются, поэтому `minio/Dockerfile` собирает сервер и `mc` из исходников по тегу релиза из `.env`. Один образ служит `minio`, `minio-init` и бэкапу.

```dockerfile
FROM golang:1.25 AS build
ARG MINIO_REF
ARG MC_REF
RUN go install github.com/minio/minio@${MINIO_REF}
RUN go install github.com/minio/mc@${MC_REF}

FROM debian:stable-slim
COPY --from=build /go/bin/minio /go/bin/mc /usr/local/bin/
```

`minio/init.sh` запускается при каждом `up`, поэтому всё в нём идемпотентно. Рядом лежат JSON-политики: `app-rw.json` — `s3:*` на `app/*`, `app-ro.json` — `s3:GetObject` на `app/*`, `people-read.json` — анонимный `s3:GetObject` на `app/people/*`.

```bash
#!/bin/sh
set -eu
mc alias set s3 http://minio:9000 "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD"
mc mb --ignore-existing s3/app
mc version enable s3/app
mc ilm import s3/app < /init/lifecycle.json            # imports/ и старые версии — 30 дней
mc anonymous set-json /init/people-read.json s3/app    # только чтение people/*, без листинга
for name in rw ro; do
  mc admin policy create s3 "app-$name" "/init/app-$name.json"
  mc admin user add s3 "app-$name" "$(cat /run/secrets/s3_$name)"
  mc admin policy attach s3 "app-$name" --user "app-$name" || true   # уже прикреплена
done
```

В dev фронт запускается через `npm run dev` с `VITE_API_PROXY=https://localhost`, то есть прокси на nginx, а не напрямую на сервис: маршрутизация по сервисам живёт в nginx. В dev `SITE_DOMAIN=localhost`, а сертификат на `localhost`, `files.localhost` и `stats.localhost` выпускает mkcert: браузеры сами отправляют `*.localhost` на 127.0.0.1, hosts править не нужно.

**CI** — `.gitlab-ci.yml` из каркаса (`lint`, `test`, `build`) с двумя добавками:

- в lint: `ruff format . --check`, `ruff check .`, `pip-licenses --partial-match --fail-on="GPL;AGPL;LGPL;SSPL"` и `pip-audit -r requirements.txt` (Apache-2.0) — известные уязвимости зависимостей;
- job фронта в test: `npm ci && npm audit --omit=dev --audit-level=high && npm test && npm run build` в `frontend/`.

## Деплой

Прод — один сервер с Docker Compose. CI собирает образы с тегом коммита и кладёт их в GitLab Container Registry, а выкатка — ручная кнопка в пайплайне ветки `main`. На сервере ничего не собирается.

1. **build** — образы `project-base`, сервисов, `nginx` с фронтом и `project-minio` собираются с тегом `$CI_COMMIT_SHORT_SHA` и пушатся в `$CI_REGISTRY_IMAGE/<имя>`.
2. **deploy** (вручную, только `main`) — по SSH на сервере: чекаут коммита (нужны `compose.yml`, `monitoring/`, `minio/`), запись тега в `.env`, `docker compose pull` и `up -d`.
3. **migrations** стартует раньше сервисов (`service_completed_successfully`): `alembic upgrade head` и заполнение пустых справочников. Упали миграции — сервисы не перезапускаются и продолжают работать на старой версии.
4. **Проверка** — `curl -fsS https://$SITE_DOMAIN/api/stats` в конце job: не ответил — job красный.

```yaml
deploy:
  stage: deploy
  rules: [{if: '$CI_COMMIT_BRANCH == "main"', when: manual}]
  script:
    - >
      ssh deploy@$PROD_HOST "cd /opt/repo
      && git fetch && git checkout --detach $CI_COMMIT_SHA
      && sed -i 's/^IMAGE_TAG=.*/IMAGE_TAG=$CI_COMMIT_SHORT_SHA/' .env
      && docker compose pull && docker compose up -d --remove-orphans"
    - curl -fsS https://$SITE_DOMAIN/api/stats > /dev/null
```

У каждого сервиса в compose рядом с `build` стоит `image`. Локально `docker compose up --build` собирает образ, а на сервере `pull` берёт готовый из реестра. `restart: unless-stopped` поднимает контейнеры после перезагрузки сервера, а тег в `.env` — ту же версию при ручном `up`.

```yaml
x-service: &service
  restart: unless-stopped

services:
  auth_service:
    <<: *service
    image: ${REGISTRY}/auth_service:${IMAGE_TAG:-dev}   # REGISTRY и IMAGE_TAG — в .env сервера
    build: {context: ., dockerfile: auth_service/Dockerfile}
  # так же остальные: имя образа у каждого своё, якорь его не подставит
```

- **Секреты CI** — protected-переменные `PROD_HOST` и SSH-ключ пользователя `deploy`, у которого на сервере есть только группа `docker`. На сервере один раз добавляется deploy-ключ на чтение репозитория (для git fetch), делается `docker login` с deploy-токеном `read_registry` и создаётся `secrets/`; секреты приложения через CI не ходят.
- **Миграции — в два релиза.** Релиз только добавляет колонки и таблицы, а удаляет старое следующий. Тогда предыдущий образ работает на новой схеме, и откат не требует `alembic downgrade`.
- **Откат** — тот же job на прошлом пайплайне («Retry» у старого deploy): тег и чекаут вернутся к прошлому коммиту. Испорченные данные чинит бэкап (раздел «Бэкапы»).
- **Простой** — секунды перезапуска контейнеров. Для сайта факультета этого достаточно, blue-green не делаем.
- **Сертификат Let's Encrypt** (если вуз не даст свой) — certbot на хосте в режиме webroot. В `server` на 80-м порту добавляется `location /.well-known/acme-challenge/ { root /var/www/certbot; }`, а после продления выполняется `docker compose exec nginx nginx -s reload`.

## Бэкапы

Каждую ночь база и файлы уходят в зашифрованный бэкап на другую машину, и потерять можно не больше суток работы. Раз в неделю бэкап автоматически восстанавливается для проверки.

| Что | Как | Почему так |
| --- | --- | --- |
| PostgreSQL | `pg_dump -Fc` под ролью `backup` с `pg_read_all_data` | Один файл, восстанавливается `pg_restore`. pg\_dump — из того же образа `postgres:17`: его версия не должна быть ниже сервера |
| MinIO | `mc mirror` префиксов `works/` и `people/` в локальную папку | Сырой каталог данных MinIO на ходу копировать нельзя: копия выйдет несогласованной |
| Шифрование, хранение, ротация | restic: репозиторий на другой машине по SFTP или в S3 вне сервера; храним 7 дневных, 4 недельных и 6 месячных снимков | Шифрует, не копирует неизменные PDF из снимка в снимок, хранит историю |

Лицензии: restic — BSD-2, `mc` — AGPL-3.0 (как MinIO), pg\_dump — PostgreSQL License.

Не бэкапим:

- RabbitMQ — очереди временные, а топологию сервисы объявляют на старте;
- Loki и Prometheus — операционные данные; Grafana — дашборды лежат в репозитории;
- веса LLM — скачиваются заново;
- `imports/` в MinIO — черновик из архива копирует PDF в `works/`, а правило жизненного цикла удаляет `imports/` через 30 дней.

**Случайное удаление файла** чинится без бэкапа. На бакете MinIO включено версионирование, старые версии удаляются через 30 дней, и удалённый или перезаписанный PDF достаётся из предыдущей версии.

**Запуск.** Сервис `backup` в compose с профилем `backup` сам не стартует; его образ — `postgres:17` с restic и `mc`. Таймер systemd или cron на хосте запускает `docker compose run --rm backup` каждую ночь. Пароль базы, ключи MinIO, адрес репозитория и пароль restic приходят через `secrets` compose, как ключи JWT.

```bash
#!/bin/sh
set -eu
pg_dump -Fc -h postgres -U backup app > /work/app.dump
mc mirror --overwrite --remove minio/app/works /work/files/works
mc mirror --overwrite --remove minio/app/people /work/files/people
restic backup /work --tag nightly
restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6 --prune
echo '{"level": "info", "service": "backup", "message": "backup ok"}'
```

Строка `backup ok` уходит в Loki, и алерт Grafana срабатывает, если её не было 26 часов. Любой упавший шаг останавливает скрипт (`set -e`), и строки не будет.

**Проверка восстановления — раз в неделю**, тем же сервисом с командой `restore-check`. Она делает `restic restore latest` во временную папку, `pg_restore` в одноразовый Postgres и сверяет число работ с файлом в базе с числом PDF в папке. Успех — строка `restore check ok` и такой же алерт на её отсутствие. Бэкап, который ни разу не восстанавливали, ничего не гарантирует.

**Восстановление после аварии:**

1. `docker compose stop` — все сервисы, кроме `postgres` и `minio`.
2. `restic restore <снимок> --target /restore`.
3. `pg_restore --clean --if-exists -h postgres -U app -d app /restore/work/app.dump`.
4. `mc mirror --overwrite /restore/work/files/works minio/app/works` и то же для `people`.
5. `docker compose up -d` — сервис `migrations` догонит схему, если бэкап старше кода.

Пароль репозитория restic хранится ещё и вне сервера, у двух человек: без него бэкап не расшифровать. Если потеря суток станет недопустимой, добавим архивацию WAL и восстановление на момент времени через WAL-G (Apache-2.0) или pgBackRest (MIT).

## Стыки с фронтом

Фронт не меняет ни одного вызова и ничего не считает сам: контракт — раздел 7 и дополнения в README фронтенда. Бэкенд держит следующее:

| Что | Требование |
| --- | --- |
| Пути | `/api/...` без имени сервиса: роутеры с `prefix="/api"`, nginx префикс не срезает |
| Сессия | Кука `__Host-session`; фронт шлёт запросы с `credentials: 'include'`, Bearer не нужен |
| Формат ошибки | `{error: {code, message}}`; у 422 ещё `fields`, у 500 — `traceId`. Любой другой формат фронт покажет как «Ошибка сервера (код)» |
| Чужое или скрытое | 404, не 403: фронт рисует «не найдено» |
| Время | ISO 8601 со смещением (`+00:00`): timestamptz в базе и aware datetime в pydantic. Время без смещения браузер прочитает как локальное |
| `X-Request-ID` | В каждом ответе, включая ответы самого nginx |
| Файлы | `FileLink {url, expiresAt}` — presigned URL MinIO |
| `fieldMeta` | `source: "ai"`, `confidence`, `lowConfidence` при значении ниже 0.7 |
| Новое: `POST /api/client-errors` | Ошибки браузера в лог: message, stack, url, userAgent, версия сборки, последний `traceId`. В catalog\_service, ответ 204; в nginx — `limit_req` и тело до 16 КБ |

Доделать во фронте:

- [ ] `api()` ловит сетевой сбой и пишет «Нет связи с сервером» вместо `Failed to fetch`
- [ ] Экран входа пишет «Неверный логин или пароль» только на 401, на остальное — текст ошибки
- [ ] `errorElement` в роутере вместо стандартного экрана React Router
- [ ] `vite:preloadError` — одна перезагрузка, если после деплоя пропал старый чанк
- [ ] «Код ошибки» из `X-Request-ID` в `ErrorState` и `Alert`
- [ ] Отправка ошибок в `/api/client-errors` через `sendBeacon`, `build.sourcemap: 'hidden'` в Vite
- [ ] `frontend/Dockerfile`, `nginx.conf.template` и `.dockerignore`
- [ ] Ссылка «Статистика» на `VITE_STATS_URL` в меню рабочего места
- [ ] Vite-прокси на `https://localhost` с `secure: false`: Node не доверяет сертификату mkcert
- [ ] Дописать в README фронтенда `POST /api/client-errors` и формат ошибки с `fields` и `traceId`

## Открытые вопросы

- **Железо под LLM.** Есть ли NVIDIA GPU и сколько у него памяти? От этого зависят vLLM или llama.cpp и размер модели.
- **Модель.** GigaChat3.1 Lightning или Qwen3.5-9B — решит замер на 20–30 ВКР с карточками, заполненными вручную.
- **Сканы.** Сколько ВКР приходит без текстового слоя и нужен ли OCR сразу?
- **Домены и сертификаты.** Какой домен у сайта (`SITE_DOMAIN`) и кто выпускает сертификат на него, `files.` и `stats.` — Let's Encrypt или вуз? Из какой сети пускать в Grafana (`STATS_ALLOW`)? Стоит ли перед сервером прокси вуза (тогда нужен `set_real_ip_from`)?
- **Учётки авторов.** Авторов сотни: создавать их командой из CSV с разовыми паролями или пускать через SSO вуза (LDAP или OIDC)?
- **Алерты.** Нужен ли GlitchTip поверх Loki для группировки ошибок и алертов, или хватит алертов Grafana?

* **Куда класть бэкапы.** Репозиторий restic должен быть вне сервера: другая машина по SFTP или S3-хранилище вуза — что есть?
* **Список трудов по ГОСТ.** Нужна ли выгрузка списка трудов преподавателя или кафедры за год (docx) для отчётов? ГОСТ-форматтер в catalog уже есть.
