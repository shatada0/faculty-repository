# ARCHIVE — репозиторий работ факультета

Каталог ВКР, курсовых, публикаций и выступлений факультета: поиск, страницы преподавателей, импорт работ с заполнением карточек ИИ.
Фронтенд — React + TypeScript + Vite (этот каталог), бэкенд — пять сервисов на FastAPI в [backend/](backend/README.md).
Спецификация — версия 0.2 (MVP к первому отчёту).

## Как запустить

Нужен компьютер с Windows 10/11, macOS или Linux, 8 ГБ памяти, около 20 ГБ на диске и интернет.

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) и запустите его. После первой установки Windows может попросить перезагрузку.
2. Для заполнения карточек ВКР искусственным интеллектом установите [Ollama](https://ollama.com/download): модель скрипт скачает сам. Без Ollama работает всё, кроме разбора PDF и списков текстом.
3. Скачайте проект (ZIP или `git clone`), распакуйте и запустите **`start.cmd`** двойным щелчком. На macOS и Linux — `sh start.sh` в терминале.

Первый запуск занимает 10–30 минут, смотря по интернету: скачивается около 4 ГБ образов, они собираются, загружаются демо-данные. Потом скрипт откроет сайт https://localhost и напишет входы:

| Кто | Логин | Пароль |
|---|---|---|
| модератор | `moderator` | `moderator123` |
| автор (Орлов Д. С.) | `orlov` | `orlov12345` |

Браузер предупредит о сертификате: стенд локальный, сертификат самоподписанный. Нажмите «Дополнительно» → «Перейти на сайт» в обеих открывшихся вкладках — вторая нужна, чтобы открывались файлы работ.

Повторный запуск — тот же `start.cmd`, около минуты; данные сохраняются. Остановить — Docker Desktop → Containers → `backend` → Stop. Что показывать — раздел [«Показ на кафедре»](#показ-на-кафедре).

**Если не запускается**
- «Docker не запущен» — откройте Docker Desktop и дождитесь надписи «Engine running».
- Ошибка про порт 80 или 443 — его занимает другая программа (IIS, Skype, другой веб-сервер): закройте её и запустите снова.
- `password authentication failed` — Docker хранит данные стенда от прошлой копии проекта с другими паролями. В папке проекта выполните `docker compose -f backend/compose.yml down -v` (удалит данные стенда, демо-данные загрузятся заново) и запустите start.cmd снова.
- Сборка или сервисы падают по памяти — Docker Desktop → Settings → Resources: дайте Docker от 6 ГБ.
- Windows спрашивает, запускать ли файл из интернета, — разрешите: «Подробнее» → «Выполнить в любом случае».
- ИИ «НЕ НАЙДЕН» на Linux — Ollama слушает только 127.0.0.1: запустите его с `OLLAMA_HOST=0.0.0.0`.
- Без видеокарты ИИ медленнее: карточка ВКР заполняется за 10–40 секунд вместо 5.
- Образы не скачиваются (Docker Hub недоступен из сети) — Docker Desktop → Settings → Docker Engine, добавьте `"registry-mirrors": ["https://mirror.gcr.io"]` и нажмите Apply.

Если Docker поставить нельзя, интерфейс можно посмотреть с имитацией сервера в браузере: нужен Node.js 20.19+, затем `npm install`, `npm run dev` и http://localhost:5173 (входы `moderator` / `moderator`, `orlov` / `orlov`; ИИ и файлы — имитация).

## Разработка фронтенда

Нужен Node.js 20.19+ или 22.12+ (https://nodejs.org, версия LTS). В папке проекта:

```bash
npm install
npm run dev        # http://localhost:5173, API на моках (VITE_USE_MOCKS=true из .env.development)
npm test           # проверки серверной логики моков и валидации
npm run build      # проверка типов + сборка; моки в продовую сборку не попадают
```

Вход на моках: модератор `moderator` / `moderator`, автор (Орлов Д. С.) `orlov` / `orlov`.
Иконка колбы в шапке включает задержки и случайные ошибки ответов. Данные хранятся в памяти и сбрасываются при перезагрузке; вход сохраняется.

## Реальный бэкенд

Задайте `VITE_USE_MOCKS=false` и `VITE_API_PROXY=https://localhost` в `.env.development.local` (пример — `.env.example`; файл с режимом в имени перекрывает `.env.development`). Прокси идёт на nginx локального стека из `backend/`, а не прямо на сервисы: маршрутизация живёт в nginx. Сертификат стека Node не проверяет (`secure: false`). Браузер передаёт свой `Origin`, поэтому бэкенд должен пускать `http://localhost:5173` (`AUTH_ALLOWED_ORIGINS` в `backend/.env`). Открывать `http://localhost:5173`, а не `127.0.0.1`.
Запросы уходят на `/api` по контракту из раздела 7; код экранов при этом не меняется.

Фронтенд ничего не считает: сводки, проверки, группировки, очереди и разбор таблиц делает сервер, экраны только показывают ответ.
Поэтому к контракту добавлено:
- работы в публичных ответах (`/works`, `/works/latest`, `/works/:id`, `/people/:id/works`) содержат `view` — готовую карточку: вид, авторы и подпись под названием (`profileId` у преподавателей, студентов и выпускников — у внешних авторов страницы нет), строка «где», аннотация для списка, метки (индексация, списки журнала, цитирования, DOI, уровень конференции, награда), строки блока «Сведения» (в том числе рубрики ГРНТИ, ОЕСР, WoS, ASJC), надпись кнопки файла (нет — текст закрыт), внешняя ссылка, `materials` — принятые материалы для скачивания; фронт только рисует их (тип `WorkView`);
- `GET /works/latest` — новые поступления для главной (сначала по одной работе каждого типа, затем самые свежие);
- `GET /works?exclude=id` — выдача без указанной работы («другие работы руководителя»);
- `q` везде (`/works`, `/works/facets`, `/people`, `/admin/works`, `/admin/people`) ищет по началу слова — «нейр» находит «нейронные» — и прощает опечатки («нейроные», «нецронных»): если точных совпадений меньше пяти, добавляются похожие по названию и ФИО, ниже точных. Кавычки, `or` и минус работают как раньше (похожие тогда не добавляются). Выдача каталога и рабочего места обновляется по мере ввода;
- `GET /works/suggest?q=` → `{ works: { id, type, title, year, parts: { text, hit }[] }[], people: { id, fullName }[] }` — подсказки строки поиска на главной (в каталоге не нужны: выдача и так обновляется при вводе): до 6 опубликованных работ и до 4 преподавателей. `parts` — название кусками, `hit` — совпавшее слово, фронт только выделяет его; пустой `q` — пустые списки, `q` не длиннее 200 символов;
- `GET /works?q=` отдаёт у каждой работы `titleParts: { text, hit }[]` — название с отмеченными совпадениями, как `parts` в подсказках; совпадения с опечаткой тоже отмечены. Без `q` поля нет;
- списки трудов по ГОСТ для отчётов, публичные docx (обычная ссылка, в моках скрыта): `GET /people/:id/works.docx?year=` — публикации и выступления человека, `GET /departments/works.docx?department=&year=` — сотрудников кафедры; 404 — нет человека или кафедры;
- `GET /departments` — кафедры: `staffCount`, `workCount` и первые три преподавателя с `shortName`;
- `GET /admin/summary` — черновики: всего, с замечаниями, по типам;
- `GET /admin/works` принимает `year`, `sort=problems` и `pageSize`;
- каждый `AdminWork` в ответах содержит все поля (`null`, если пусто — как сериализует pydantic), `actions` — что можно сделать сейчас (`publish`, `unpublish`, `reject`; иначе publish/unpublish/reject отвечают 409), `errors` — `{ field, message }[]`, что мешает публикации (`field` — путь через точку, как `loc` у pydantic: `event.dateEnd`, `authors.0.displayName`), `issues` (всё, на что смотреть: ошибки, неуверенный ИИ, нераспознанные авторы) и `importFileName`, а в `fieldMeta` сервер ставит `lowConfidence`; при записи эти поля игнорируются;
- `fieldMeta` ведёт сервер: фронт его не присылает; при `POST`/`PATCH /admin/works` поля, отличающиеся от сохранённой версии (у новой — от шаблона), получают источник `manual`;
- `GET /admin/works/template?type=` — новая работа со значениями по умолчанию (с неё начинается редактор);
- `POST /admin/works/:id/doi` `{ doi, overwrite? }` → `{ work, conflicts: { field, label, current, incoming }[] }` вместо `GET /admin/doi-lookup`: сервер заполняет пустые и нетронутые поля (источник `doi`), а заполненные и отличающиеся возвращает конфликтами, пока их не перечислят в `overwrite`; редактор перед этим сохраняет работу (новая становится черновиком); на бэке данные берутся из Crossref (`api.crossref.org/works/{doi}`), 400 — неверный формат, 404 — DOI не найден;
- `GET /upload-limits` → `{ archive, table, workFile, material }` с `accept` и `maxBytes` (публичный: нужен и автору) — фронт проверяет файл до загрузки, но лимиты задаёт сервер;
- курсовая — работа или проект: `StudentWork.kind` = `work` | `project` (у ВКР нет); фильтр каталога `courseKind`; в таблице импорта курсовых колонка «Работа или проект»;
- `subjects: { scheme, code, name }[]` у любой работы — рубрики классификаторов `grnti` (ГРНТИ), `oecd` (ОЕСР), `wos` (категории Web of Science), `asjc` (области Scopus); редактор ищет по `GET /admin/classifiers/:scheme?q=` → `Subject[]`; фильтры каталога `grnti` (все вкладки), `oecd`, `wos`, `asjc` (публикации);
- у публикаций только для чтения `citations` (из Crossref / Scopus / РИНЦ) и `journalLists` — подписи списков журнала из справочника журналов по ISSN («Белый список, уровень 2», «ВАК, К1», «RSCI», «Scopus Q2», «WoS Q3»); фильтр каталога `journalList` по кодам списков;
- страницы людей: `GET /people/:id` отдаёт и студентов с выпускниками (у внешних — 404); в ответе `headline`, `tiles` (`{ value, label, note }[]`) и `tabs` (`{ key, label, count, query, filters }`) — что показывать, считает сервер, `query` уходит в `/people/:id/works`; поля `counts`, `byIndexing`, `byConfLevel` убраны;
- `GET /people/:id/metrics?year=` → `{ items: StatTile[], years }` — индекс Хирша и цитирования по публикациям человека, за все годы или по работам одного года;
- роль `author` у пользователя с `personId` (вход тот же, `/auth/me` отдаёт `role` и `personId`): `GET /my/works` → `{ items: MyWork[] }`, `POST /my/works/:id/materials` (multipart: `file`, `kind` = `text` | `slides` | `data` | `other`) → `Material` со статусом `pending`, `DELETE /my/works/:id/materials/:mid` — только `pending`; на `/admin/*` автору — 403;
- материалы: у `AdminWork` есть `materials`, модератор принимает или отклоняет их через `POST /admin/works/:id/materials/:mid { status }` → `AdminWork` и открывает через `GET /admin/works/:id/materials/:mid` → `FileLink`; публично принятые отдаются по `GET /works/:id/materials/:mid` → `FileLink`; в `GET /admin/summary` есть `pendingMaterials`;
- `POST /admin/works/bulk` `{ ids, action: 'publish' | 'access', accessLevel }` → `{ done, skipped }`; сервер сам проверяет каждую работу (в том числе согласие студента);
- `GET /admin/works/next?after=id&type&importId` → `{ id }` — следующая работа в очереди проверки;
- `GET /admin/works/related-options?type&author&include` → `{ id, label }[]` — работы с общими авторами для поля «связанный доклад / публикация»;
- `POST /admin/imports/preview` (multipart: `workType`, `file`) → заголовки, первые 10 строк, `total`, `bad`, `missingColumns`;
- `GET /admin/imports/:id?status=` — фильтр элементов; в `stats` есть `processed`, `unmatched` и `published`;
- ВКР и курсовые загружаются одним вариантом: `POST /admin/imports` с `kind=archive` принимает поле `file` сколько угодно раз, `.pdf` и `.zip` вперемешку (лимит `upload-limits.archive.maxBytes` — на всю загрузку). Тип каждой работы, ВКР или курсовую (и у курсовой — работа или проект), сервер узнаёт по титульнику; `workType` нужен, только если титульник не помог. Автору без профиля сервер заводит выпускника или студента, если ФИО есть в тексте PDF. Рубрики ставятся по коду направления из справочника (`fieldMeta.subjects.source = 'direction'`). Карточка без `errors` и `issues` и не дубль публикуется сразу (`accessLevel: card_only`, текст закрыт до согласия), у элемента статус `published`; остальные ждут в очереди проверки со статусом `filled`;
- `GET /admin/templates/:type/columns` → `{ name, required }[]`;
- `GET /admin/people` принимает `exclude` и находит «Иванов И. И.» по «Иванов Иван Иванович»; люди в ответах `/admin/people` содержат `shortName`;
- `POST /admin/people` и `PATCH /admin/people/:id` проверяют ФИО и ORCID (400 с текстом ошибки); в `PATCH` очищенное поле приходит `null`, а поле, которого нет в теле, не меняется;
- `POST /admin/people/:id/orcid-import` → `{ found, created, known, notFound, failed, message }` — работы с DOI из публичного профиля ORCID и найденные OpenAlex по тому же ORCID становятся черновиками публикаций, заполненными по Crossref; уже известные DOI пропускаются, совпавшие по названию и году получают `duplicateOf`; владелец профиля привязывается к своему написанию в статье, даже если есть однофамилец; `message` — готовая сводка для показа; 400 `no_orcid` — ORCID не указан;
- `POST /admin/works/doi-import` `{ text }` → тот же ответ, что у импорта из ORCID: DOI ищутся в тексте (через пробелы, запятые, строки, ссылками doi.org), не больше 1000; 400 `doi` — DOI в тексте нет;
- `POST /admin/works/:id/isbn` `{ isbn, overwrite? }` → `{ work, conflicts }`, как `/doi`: книга по ISBN из Crossref, иначе из Open Library; источник полей — `isbn`; 400 `isbn` — неверный контрольный знак, 404 — нигде нет;
- `POST /admin/imports` с `kind=text` и полем `text` (вместо `file`) — список публикаций или докладов текстом: записи пронумерованы («1. …») или разделены пустыми строками; каждую ИИ разбирает в строку шаблона таблицы, элементы `pending` → `filled`/`error`, черновики ждут модератора, `fieldMeta` — `ai` с уверенностью; «Повторить» работает, как у архива; `Import.kind` = `archive` | `table` | `text`; 400 `bad_text` — записей нет;
- `kind=table` для публикаций принимает и `.bib` (BibTeX) и `.ris` — выгрузки Scopus, Web of Science, Google Scholar, Zotero, Mendeley: записи читаются как строки шаблона (`ref` — «Запись N»), источник полей — `bibliography`, записи Scopus и WoS получают индексацию; у монографии и учебного пособия колонка «Журнал/сборник» не обязательна;
- у `Person` есть `spin` (SPIN-код РИНЦ, `1234-5678`) и `elibraryId` (AuthorID РИНЦ, цифры), а `elibraryUrl` — ссылку на страницу автора в eLIBRARY — строит сервер; 400 `bad_spin` / `bad_elibrary_id`;
- `GET /admin/people/:id` возвращает также `works` (список работ человека);
- `POST /admin/people/match-external` `{ names }` → `{ done }` — «Остальные — внешние авторы» на вкладке «Нераспознанные авторы»: каждое написание становится новым внешним автором, как по кнопке «Внешний автор» (одной транзакцией); написания, которые уже привязаны, пропускаются;
- `GET /people/:id` и `GET /admin/people/:id` для объединённого профиля отдают основной профиль — фронт сам переходит на его id;
- у `StudentWork` есть поле `consent` (согласие студента), у `Person` — `aliases` (варианты написания ФИО);
- выгрузки модератора, ответ — файл с `Content-Disposition`: `GET /admin/exports/works?type&status&year&importId&q&format=xlsx|csv` — работы по фильтрам «Всех работ» в колонках шаблона импорта типа (без типа — общие колонки) плюс `id`, статус, уровень доступа и ссылка на карточку; `GET /admin/exports/works.zip?…` — то же в `works.xlsx` и PDF в `files/{id}.pdf`, отдаётся потоком, поэтому фронт ставит обычную ссылку, а не `download()`; `GET /admin/exports/people?format=xlsx|csv` — люди с вариантами написания и числом работ. csv — UTF-8 с BOM и `;`, как ждёт русский Excel;
- `POST /client-errors` `{ message, stack, url, userAgent, build, traceId }` → 204 — ошибка в браузере уходит в логи бэкенда: фронт шлёт её через `sendBeacon` из `window.onerror`, `unhandledrejection` и экрана ошибки роутера; `build` — `VITE_BUILD` (в CI — короткий SHA коммита), `traceId` — последний `X-Request-ID`. Sourcemap собираются (`build.sourcemap: 'hidden'`), но наружу nginx их не отдаёт.

Ошибки приходят в одном виде: `{ error: { code, message } }`. У 422 (тело не прошло проверку) есть ещё `fields: { field, message }[]` с путём через точку, у 500 — `traceId`. Каждый ответ, в том числе 502 и 504 самого nginx, несёт заголовок `X-Request-ID`: на 5xx `ApiError` дописывает его к сообщению как «Код ошибки», и по нему запрос находится в логах. Сбой сети (`fetch` не получил ответа) — `ApiError` со статусом 0 и текстом «Нет связи с сервером». Перебор пароля nginx режет ответом 429 `rate_limited`; экран входа пишет «Неверный логин или пароль» только на 401, на остальное — текст ошибки.

Валидации на фронте нет: редактор показывает `errors` с сервера при открытии и после каждого сохранения. На фронте остаются только подписи для фильтров и полей редактора, форматирование дат и склонений, состояние в URL и кэш запросов.

## Показ на кафедре

Показывать на настоящем стенде (`backend/`, сайт https://localhost); моки — запасной вариант, если Docker на месте не запустится.

### Перед показом

1. Стенд запущен `start.cmd` (раздел «Как запустить»), в его сводке «ИИ: работает». Без Ollama импорт ВКР и списков текстом встанет в очередь и не заполнится.
2. Если на стенде уже репетировали — `sh backend/scripts/demo-reset.sh` (на Windows из Git Bash): чистая база с демо-данными и теми же входами. Старая база не удаляется: скрипт копирует её в том `backend_pgdata_<дата>`, команда возврата — в шапке скрипта.
3. Сертификат принят в обеих вкладках, которые открыл `start.cmd`: https://localhost и https://files.localhost (иначе PDF рядом с карточкой в редакторе будет пустым). Для Grafana — ещё https://stats.localhost, логин `admin`, пароль — в сводке `start.cmd`. Без предупреждений — поставить [mkcert](https://github.com/FiloSottile/mkcert), `mkcert -install`, удалить `backend/certs/`, снова `sh scripts/dev-secrets.sh` и `docker compose restart nginx`.
4. Нужен интернет: DOI и ISBN ищутся в Crossref и Open Library.
5. Файлы для импорта — в папке `демо/` (там же `ПРОЧТИ.txt`).

### Сценарий (≈15 минут)

1. Гость: главная → в поиске «нейронные сети» (подсказки по мере ввода) → каталог: совпадения подсвечены, слева фильтры → вкладка «Публикации» → тезисы → «Доклад по этой работе» и «Как цитировать» по ГОСТ.
2. Автор Орлов Д. С. → профиль: плитки, «Цитирование» (индекс Хирша, выбор года пересчитывает), диаграмма по годам (клик по столбцу — работы этого года), «Список трудов по ГОСТ (docx)».
3. «Вход» → `moderator` → «Сводка»: черновики, последние импорты, материалы от авторов.
4. «Новый импорт» → «ВКР и курсовые» → три PDF из `демо/1 ВКР с текстом`. Через 10–15 секунд ИИ заполнил карточки, и они опубликовались сами.
5. Туда же `демо/2 Скан ВКР`: текстового слоя нет, текст читает OCR. Карточка ждёт проверки → «Проверить черновики» → редактор: PDF рядом, поля «ИИ… — проверьте» подсвечены → «Опубликовать».
6. «Публикации файлом» → `демо/3 Таблицы/Публикации.csv`: предпросмотр, строки с пропусками станут ошибками, остальные — черновиками → «Разобрать авторов» → «Связать» / «Создать нового» / «Внешний автор».
7. «Публикации по DOI» → три DOI из `демо/6 DOI и ISBN.txt` → черновики по Crossref.
8. «Все работы» → «Добавить работу» → «Публикация» → DOI вверху формы (например, `10.1016/j.jcp.2015.10.015`) → «Заполнить по DOI» → «Опубликовать» → работа в каталоге.
9. «Выйти» → `orlov` → «Мои работы» → «Добавить материал». Снова `moderator` → «Сводка» → «Материалы от авторов» → «Принять» → файл на странице работы.

На моках (`npm run dev` без бэкенда) сценарий тот же, входы `moderator` / `moderator` и `orlov` / `orlov`, импорт ВКР заполняет карточки каждые 3 секунды по «Демо-таблице», DOI — `10.12345/kim.2026.0142`, `10.12345/jads.2025.118`, `10.12345/pi.2026.07`, `10.12345/mmnm.2025.31`, `10.12345/ijse.2026.0093`.

## Структура

```
src/api         типы (раздел 4), клиент и функции эндпоинтов (раздел 7)
src/mocks       MSW — модель бэкенда: сид, поиск/фасеты, проверки черновиков (zod вместо pydantic), ФИО, ГОСТ, таблицы импорта, обработчики, панель настроек
src/routes      страницы (раздел 5), src/routes/admin — рабочее место модератора
src/components  UI-кит, карточки работ, фильтры, редактор авторов, загрузка файлов
src/lib         подписи, даты и склонения, набор фильтров по вкладкам каталога
```

Компоненты в стиле shadcn/ui написаны на нативных элементах (`<dialog>`, `<select>`) в `src/components/ui.tsx`, без Radix.

## Оформление

Макет — «Репозиторий работ факультета». Работы показаны списками с тонкими линиями, как в библиотечном каталоге. Шрифт один на весь сайт — Montserrat (OFL, с кириллицей, подключён локально через `@fontsource`): свободная замена Motiva Sans из Steam, который лицензирован только для Valve. Из визуального кода вуза взяты красный акцент, прямые углы, ссылки-кнопки капсом и блок крупных цифр из стыкующихся плиток. Цвета — красный акцент вуза в паре с тёмно-синим `brand` (плитки, линии, рамки, график), чёрный `ink` — текст, тонкая полоса над шапкой и линия подвала, светлые серо-голубые панели; токены в `src/index.css` (`ink`, `brand`, `panel`, `accent`, `warn`, `danger` и др.). Название в верхней полосе задаётся переменной `VITE_FACULTY_NAME`.

Название сайта — «ARCHIVE»: нейтрально и понятно без пояснений; задаётся константой `SITE` в `src/components/Layout.tsx`. Знак — вход в архив: арка с красным замковым камнем и полками книг. Файлы в `public/`: `logo.svg` — основной, `favicon.svg` — упрощённый для иконки вкладки (три книги вместо полок), `logo-on-dark.svg` — для тёмного фона.
